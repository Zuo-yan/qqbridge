# 消息防抖合并

> **原项目**：[Message Debouncing](https://github.com/tackyeel/Message-Debouncing)
> 本项目在其基础上重构，提供对**更高版本 MaiBot** 的支持。
>
> **本项目由 Qwen3.8-Max-Preview 编写。**

一个 MaiBot 消息预处理插件，用来把短时间内同一会话、同一用户连续发来的多条消息合并成一条，再交给 MaiBot 处理。

适合用户习惯分段发送的场景，例如：

```text
你在吗
我刚刚想到一件事
能不能帮我看一下
```

插件会先等待一个很短的防抖窗口。如果同一用户继续发送消息，就继续合并；窗口结束后，只放行合并后的消息。这样可以减少半句话触发回复、重复思考、抢话和上下文割裂。

## 功能

- 支持私聊和群聊。
- 默认只合并同一用户的连续消息，避免把群里不同人的话混在一起。
- 支持忽略命令消息，命令会直接放行。
- 支持文本、图片、表情、语音、转发等主体消息。
- 提供中文 WebUI 配置项和详细日志。

## 安装

将 `Message_Debouncing_Refactored` 文件夹放入 MaiBot 的 `plugins/` 目录下，启动 MaiBot 后插件会自动被发现和加载。也可以通过 WebUI 插件管理页面进行启用/禁用。

## 默认配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 启用插件 | 是 | 总开关 |
| 防抖等待秒数 | 2.0 | 收到消息后等待多久再结算 |
| 最长等待秒数 | 8.0 | 单轮合并最多等待多久 |
| 合并分隔符 | 换行 | 多条文本合并时的分隔符 |
| 私聊启用 | 是 | 是否在私聊中启用 |
| 群聊启用 | 是 | 是否在群聊中启用 |
| 只合并同一用户 | 是 | 群聊中是否只合并同一人的消息 |
| 命令直接放行 | 是 | 命令消息不参与防抖 |
| 命令前缀 | /, !, ！ | 用于识别命令的前缀列表 |
| 忽略空消息 | 是 | 无主体内容的消息不参与防抖 |
| 记录详细日志 | 是 | 是否记录防抖过程日志 |

配置可通过 WebUI 插件管理页面修改，修改后自动热重载，无需重启。

## 工作原理

1. 收到入站消息时，插件通过 `chat.receive.before_process` Hook 拦截。
2. 判断消息是否需要参与防抖（非通知、非命令、对应聊天类型已启用）。
3. 如果是该会话窗口的首条消息，创建防抖窗口并启动定时器，消息被暂时挂起。
4. 如果窗口已存在，追加消息并重置定时器。
5. 定时器到期后，合并窗口内所有消息为一条，放行给 MaiBot 后续处理。
6. 如果窗口内只有一条消息，直接放行不做合并。

## 注意事项

- 这个插件只处理"收到的用户消息"。如果机器人自己的回复被拆成多条发送，那是回复分割器或发送策略导致的，不属于本插件处理范围。
- 群聊中建议保持"只合并同一用户"开启，避免多人同时说话时被错误合并。
- 防抖等待秒数越大，越能等到用户把话说完，但回复延迟也会增加。推荐 1.5 到 3 秒。
- 最长等待秒数用于防止用户一直连发导致 MaiBot 永远不处理。推荐 6 到 12 秒。
