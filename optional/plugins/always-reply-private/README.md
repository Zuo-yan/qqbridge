# 🤫 私聊必回复插件 v2.5 (always-reply-private)

一个专门用于提升 MaiBot 私聊体验的辅助插件。在开了时机模型情况下，它能让你的 Bot 无论遇到多么简短、模糊的私聊输入，都 **100% 触发回复**，绝不漏回、绝不冷场，并且支持配置白名单用户。

---

## ⚠️ 重要提示：前置要求

**本插件的作用是"在私聊中跳过时机模型"，因此需要确保 MaiBot 已开启时机模型功能。**

- 📍 在 **WebUI → 设置 → 聊天设置** 中，确认**时机模型已开启**
- ❌ 如果时机模型未开启，本插件不会生效（因为没有时机模型可跳过）
- 💡 关闭时机模型后，MaiBot 会对所有消息（包括私聊和群聊）直接进入 Planner，此时无需本插件
- 🎯 本插件只影响**私聊消息**，不会改变群聊的时机模型判断行为

---

## ✨ 核心特性

- 🚀 **跳过时机模型**：在私聊场景下，直接跳过时机模型（Timing Gate）判定，不再消耗 Token 去询问模型"我该不该回复"，缩短响应时间，实现秒回！
- 🎯 **多适配器支持**：深度适配 QQ (NapCat/GoCQ)、Telegram、Discord 等多适配器传递的异构消息格式，精准识别私聊事件。
- 🛡️ **用户白名单模式**：
  - 默认对**所有私聊用户**生效（私聊必回复）。
  - 可配置白名单，只有列表内的特定账号才会触发"私聊必回复"，普通私聊用户依然走原版的时机模型，兼顾群管和隐私。
- ⚙️ **完美支持 SDK 2.0 与 WebUI**：支持配置热更新（Hot Reload）以及 WebUI 的动态配置 Schema 管理。
- 🔧 **智能去重**：自动过滤通知消息和已设置标志的消息，避免重复处理。
- 🧠 **Planner 强制回复提示**：在 Planner 请求模型前注入系统指令，大幅降低 Planner 选择 `wait` 或不调用 `reply` 的概率。

## 🆕 v2.5.0 重大更新

### 🎯 修复默认配置下不生效的问题

**v2.0.0 的问题**：
- 只设置 `is_mentioned` 标志，依赖 `mentioned_bot_reply` 配置开关
- 但 MaiBot 默认配置中 `mentioned_bot_reply = False`
- 导致插件在默认配置下**无法触发强制跳过**，私聊仍然走正常时机模型

**v2.5.0 的解决方案**：
- ✅ 保留 `is_mentioned = True` 作为语义标记（让 Planner 知道这是"提及"而非"@"）
- ✅ 额外向 `message_info.additional_config` 注入数值型 `is_mentioned = 1.0`
- ✅ 使 `reply_probability_boost >= 1.0`，直接触发 `_arm_forced_turn`
- ✅ **不再依赖 `mentioned_bot_reply` 开关**，默认配置下即可生效
- ✅ 仍然保持私聊环境的纯粹性，不会误判为群聊被艾特

### 🛠️ 兼容性说明

v2.5.0 同时兼容 MaiBot 的两种回复触发模式：
- **frequency 模式**：通过 `reply_probability_boost` 直接触发 forced turn
- **reply_necessity 模式**：`is_mentioned` 标记提供 80 分提及分，配合私聊基础分确保进入 Planner

### 🧠 新增 Planner 强制回复提示

**问题**：即使成功绕过时机模型进入 Planner，LLM 仍可能自主决定：
- 调用 `wait` 工具等待
- 输出空工具（no tool）
- 只查询记忆/历史而不调用 `reply`

**v2.5.0 的解决方案**：
- ✅ 订阅 `maisaka.planner.before_request` Hook
- ✅ 在 Planner 请求模型前，向 `messages` 追加一条系统指令
- ✅ 明确告知模型"当前是私聊，必须调用 reply 工具回复"
- ✅ 显著降低 Planner 不回复的概率

> ⚠️ 注意：这能大幅提高回复概率，但仍受 LLM 能力影响，无法保证绝对 100%。建议使用较强的 planner 模型以获得最佳效果。

## 🆕 v2.0.0 重大更新

### 🎯 核心实现方式完全重写

**v1.5.0 的问题**：
- 通过注入 `force_continue`、`force_reply`、`is_at` 等标记来绕过时机模型
- 这些标记可能与 Planner 的实际逻辑产生冲突
- 特别是 `is_at` 标记会让 Planner 误以为当前是**群聊被艾特场景**，影响回复质量和上下文理解

**v2.0.0 的解决方案**：
- ✅ **只设置 `is_mentioned` 标志**，不再设置 `is_at`
- ✅ 利用 MaiBot 原生的 `_update_message_trigger_state` 机制自动触发强制跳过
- ✅ 保持私聊环境的纯粹性，Planner 能正确理解当前是私聊而非群聊
- ✅ 不需要直接操作 runtime 实例，实现更优雅、更稳定

### 🛠️ Hook 时机调整

**v1.5.0**：使用 `chat.receive.before_process` + `HookOrder.EARLY`

**v2.0.0**：使用 `chat.receive.after_process` + `HookOrder.LATE`

- 在消息完成轻量预处理后再进行判断，信息更完整
- 避免过早介入导致的消息格式不完整问题

### 🚫 智能过滤

新增两个重要的过滤机制：

1. **自动跳过通知消息**：
   - 用户输入状态通知 (`input_status`)
   - 其他 `is_notify=true` 的事件
   - 避免无效触发和日志噪音

2. **避免重复处理**：
   - 如果消息已经有 `is_mentioned` 或 `is_at` 标志，自动跳过
   - 防止多次设置导致的逻辑混乱

## 🛠️ 实现原理对比

### v1.5.0 实现（旧版）

```
用户消息 → before_process Hook (EARLY)
         → 判断私聊 + 白名单
         → 注入 force_continue + force_reply + is_at 标记
         → 消息进入 Host
         → 推理引擎检测覆盖标记
         → 绕过时机模型 ✓
         → 但 Planner 误以为是群聊被艾特 ✗
```

### v2.5.0 实现（新版）

```
用户消息 → 消息预处理
         → after_process Hook (LATE)
         → 判断私聊 + 白名单 + 过滤通知
         → 设置 is_mentioned 标志
         → 注入 additional_config.is_mentioned = 1.0（概率提升）
         → 记录会话 ID 到待强制回复集合
         → 消息进入 Maisaka runtime
         → _update_message_trigger_state 检测到 is_mentioned 且 reply_probability_boost >= 1.0
         → 自动调用 _arm_forced_turn
         → 绕过时机模型 ✓
         → Planner 正确理解是私聊环境 ✓
         → 默认配置下也能生效 ✓
         → before_request Hook 注入强制回复系统指令
         → Planner 更大概率调用 reply 工具 ✓
```

## ⚙️ 配置文件说明 (`config.toml`)

本插件支持在 WebUI 面板中直接可视化修改配置。其生成的配置文件位于插件目录下的 `config.toml`，内容格式如下：

```toml
[plugin]
config_version = "2.5.0"
enabled = true                    # 是否启用该插件
whitelist_users = ""              # 白名单用户 ID，多个用英文逗号分隔（例: "1234567,7654321"）
                                  # 留空表示对所有私聊用户生效
```

**配置说明**：

- **`enabled`**：控制插件开关，设为 `false` 可暂时禁用插件而无需卸载
- **`whitelist_users`**：
  - 留空（`""`）= 对**所有私聊用户**生效，私聊必回复
  - 填写 ID（`"123456,789012"`）= 只对白名单用户生效，其他私聊用户走正常时机判断

## 🚀 安装使用

### ⚠️ 前置要求

**本插件的作用是"跳过时机模型"，因此需要确保 MaiBot 已开启时机模型功能。**

- 在 WebUI → 设置 → 聊天设置 中，确认**时机模型已开启**
- 如果时机模型未开启，本插件不会生效（因为没有时机模型可跳过）
- 关闭时机模型后，MaiBot 会对所有消息直接进入 Planner，此时无需本插件

### 全新安装

1. 将本插件文件夹放入 MaiBot 的 `plugins/` 目录下
2. 启动或重启 MaiBot，插件会自动被加载
3. **确认 WebUI 中已开启时机模型**
4. （可选）进入 WebUI → 插件管理 → 私聊必回复 → 修改白名单配置

### 从 v1.5.0 升级

1. **备份旧版配置**（如果你自定义了白名单）
2. 删除旧版插件文件夹 `always-reply-private`
3. 将 v2.5.0 插件文件夹放入 `plugins/` 目录
4. 重启 MaiBot
5. **确认 WebUI 中已开启时机模型**
6. 在 WebUI 中重新配置白名单（配置格式相同，可直接复制粘贴）

**注意**：v2.5.0 的配置文件与 v1.5.0 / v2.0.0 **完全兼容**，`whitelist_users` 格式没有变化。

### 从 v2.0.0 升级

1. **备份旧版配置**（如果你自定义了白名单）
2. 直接用 v2.5.0 覆盖 `always-reply-private` 文件夹
3. 重启 MaiBot

**注意**：v2.5.0 修复了 v2.0.0 在默认配置下不生效的问题，无需手动开启"提及必回复"开关。

## 🔧 故障排查

### 插件不生效？

1. **⚠️ 首先确认时机模型已开启**：
   - 进入 WebUI → 设置 → 聊天设置
   - 确认**时机模型功能已开启**
   - **如果时机模型未开启，本插件不会生效**

2. **检查插件是否加载**：
   - 查看启动日志中是否有 `[plugin.always-reply-private] 私聊必回复插件已加载`

3. **检查白名单配置**：
   - 如果设置了白名单，确认你的用户 ID 在列表中
   - 留空白名单则对所有私聊生效

4. **检查 `enabled` 配置**：
   - 确认 `config.toml` 中 `enabled = true`

5. **查看日志**：
   - 发送私聊消息后，查找 `[plugin.always-reply-private]` 相关日志
   - 应该能看到 `✓ 私聊消息设置 is_mentioned 标志`

### 仍然调用了时机模型？

- **再次确认时机模型是否已开启**（这是最常见的问题）
- 检查是否是**通知消息**（如输入状态），这类消息会被自动过滤
- 确认消息确实是私聊消息，而非群聊消息
- 查看日志确认插件是否真的被触发

## 💡 使用建议

1. **默认配置最佳**：对于大多数场景，留空白名单（对所有私聊必回复）是最佳选择
2. **白名单适用场景**：
   - 你的 Bot 同时有公开服务和私人管理功能
   - 只希望对特定管理员或测试账号启用必回复
   - 需要精细控制不同用户的回复策略
3. **与其他插件配合**：v2.0.0 的实现方式更加优雅，与其他插件的兼容性更好
