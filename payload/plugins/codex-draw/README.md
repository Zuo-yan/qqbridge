# Codex 绘图插件（codex-draw）

麦麦可通过 codex 调用 gpt-image2 进行绘画。
通过本机已安装的 [codex CLI](https://github.com/openai/codex) 生成或编辑图片，并把结果回传到当前聊天流。
使用者需要自行准备可用的 Codex 订阅，以及合规审查所用 VLM 的服务与额度。

## 兼容性

- MaiBot `1.0.0` 至 `1.99.99`
- maibot-plugin-sdk `2.7.0` 至 `2.99.99`
- Python 版本跟随 MaiBot（当前要求 Python 3.10 或更高版本）

## 安装

在 MaiBot 根目录执行：

```bash
git clone https://github.com/SawataLi/codex-draw.git plugins/codex-draw
```

本插件没有额外的 Python 第三方依赖；`requirements.txt` 仅用于说明依赖情况。完成下方的 Codex CLI 安装与登录后，启动或重载 MaiBot，并在 WebUI 中启用插件。

## 前置条件

1. **安装并登录 codex**（本插件不托管登录）：
   ```bash
   codex --version        # 确认已安装
   codex login            # 在终端自行完成登录
   ```
2. **代理**：codex 出图需要走代理。默认使用本机 `127.0.0.1:7890`，可在 WebUI 修改。
3. **合规审查模型**：默认使用 MaiBot 中任务名为 `vlm` 的多模态模型；请确保该模型已配置且有可用额度。

## 用法

- **生成**：在聊天中发送
  ```
  /gpt 一只红色的立方体，白色背景
  ```
- **编辑**：以下两种方式任选，插件会取参考图触发 codex 的图片编辑：
  1. 先发送/引用一张图片，**回复该图片**后再发送 `/gpt 把背景换成深蓝色`（取被回复消息里的图）；
  2. 或**在同一条消息里同时发送图片和 `/gpt 把背景换成深蓝色`**（取本条消息里的图）。

任务在后台执行。合规审查通过后会回复「GPT-image2绘制中」，出图完成后把图片发到当前聊天流；
审查不通过时静默拒绝，不发送聊天消息。
生成和编辑任务不排队，默认最多同时执行 4 个，可在 WebUI 调整。达到并发上限时，
新请求会被静默忽略，不调用合规 VLM 或 codex，也不会向聊天流发送提示。

   **邪修用法**：利用codex中gpt5.6的主观能动性，可以让gpt自行搜索网络信息后以图片形式返回结果：
   ```
   /gpt 调查XXX游戏今晚的直播，总结直播内容，绘制新版本情报海报
   ```
   耗时可能较长，需要适当拉长超时时间，推荐使用廉价且快速的GPT5.6luna作为调查模型。

- **仅审查（不出图）**：发送
  ```
  /gpt 审查 <提示词>
  ```
  只触发一次合规审查并回复裁决（`✅ 通过` / `❌ 未通过`，不返回具体理由）。
  英文可用 `/gpt check <提示词>` 或 `/gpt review <提示词>`。
  回复一条含图片的消息再发该命令，会连同参考图一起审查。

## 合规审查、安全与信任边界

送入 codex 前，插件会另起一个上下文的多模态 LLM 对提示词进行合规审查，编辑时会连同参考图一起审查。
默认使用 MaiBot 的多模态视觉模型（任务名 `vlm`）。审查采用“明确命中严重违规才拒绝，
边界或信息不足时通过”的原则，不会只因敏感关键词、人物身份、画风或题材名称拒绝。

该审查只是尽力而为的业务门禁，不是安全边界，可能出现误判或漏判，也不能保证 Codex 账号不会受限。
插件运营者仍需对实际请求、生成内容、账号使用方式和部署环境负责。

启用合规审查时，生成或编辑的提示词和参考图会先交给配置的 VLM，再交给本机 codex CLI。
这些组件是否继续连接第三方服务、如何存储和处理数据，取决于 MaiBot、VLM 与 codex 的实际配置。

`codex.codex_path` 是管理员可配置的可执行文件路径，插件会直接启动该程序。
请只允许可信管理员修改插件配置，并指向可信的 Codex CLI；生产环境建议使用经过核验的绝对路径。
`--sandbox workspace-write` 约束的是可信 Codex Agent 的工作区权限，不能防护被替换或恶意的可执行文件。

生成或编辑请求可能同时消耗一次 VLM 审查额度和 Codex 订阅额度；审查未通过时仍会消耗 VLM 额度。
`/gpt 审查` 只消耗 VLM 额度。插件不统计或限制累计用量、费用或订阅额度，
并发限制只控制同时运行的出图任务；相关订阅、额度、费用与账号风险均由插件运营者自行承担。

## 配置（WebUI → 插件配置 → codex-draw）

| 字段 | 说明 | 默认 |
|---|---|---|
| `codex.codex_path` | codex 可执行文件路径 | `codex` |
| `codex.proxy_url` | HTTP 代理（`host:port`），留空则清除子进程继承的代理环境变量并直连 | `127.0.0.1:7890` |
| `codex.model` | codex 对话/代理模型，留空用 codex 默认 | 空 |
| `codex.reasoning_effort` | codex 代理思考努力，留空用 codex 默认 | `medium` |
| `codex.timeout_seconds` | 连续无活动超时（秒），有活动则继续等待；总时长另受固定 30 分钟上限约束 | `180` |
| `codex.max_concurrent_jobs` | 同时执行的生成/编辑任务上限；满载时静默忽略新请求，不排队 | `4` |
| `codex.generated_dir` | codex 产物目录，留空用 `$CODEX_HOME/generated_images` | 空 |
| `compliance.enabled` | 是否启用合规审查 | `true` |
| `compliance.review_model` | 审查用的 maibot 模型任务名 | `vlm` |
| `compliance.timeout_ms` | 审查调用超时（毫秒） | `60000` |

配置修改后热更新生效，无需重启机器人。

出图期间每 0.2 秒检查完整图片，每 5 秒检查本次 Codex 会话记录是否更新，
并持续监听结构化事件。工具轮询等待记录或图片写入有更新时，会重新计算无活动时长；
例如配置为 `600` 时，累计超过 600 秒仍可继续等待；连续 600 秒无活动，或累计达到
30 分钟仍未出图，都会终止进程组并释放并发名额。30 分钟上限从 Codex 进程启动后计时，
不会被活动信号刷新，也不受无活动超时配置影响；两种限制谁先触发就先终止。
进程存活本身不算活动，普通 stderr 日志也不会刷新计时。图片完整落盘后立即回传。
超过首个等待窗口后，日志会定期记录累计等待时间、无活动时间和最近活动来源。

会话记录按 `$CODEX_HOME/sessions` 下当前会话 ID 匹配，独立于 `generated_dir`。
没有会话记录时，仅依据结构化事件和图片写入判断；如果单次工具调用完全静默，
仍可能触发无活动超时，应按实际静默时长调整此配置。持续返回“运行中”表示等待链路仍在响应，
无法证明远端绘图服务一定有进展，因此设置独立的 30 分钟总时长上限；卸载插件也可取消任务。

仓库中的 `config.example.toml` 只用于展示公开默认值，插件不会直接读取它。
运行时 `config.toml` 由 MaiBot Runner 根据插件的 `config_model` 自动生成和维护，不纳入 Git。
请勿把本机凭证、令牌或其他敏感信息提交到插件仓库。

## 错误提示

- **未登录**：提示「请先在终端执行 `codex login`」。
- **网络/代理异常**：提示检查代理设置（可在 WebUI 改 `proxy_url`）。
- **出图失败**：回传 codex 的真实报错信息。

## 大肥鱼部署补丁 0.1.1（2026-10-26）

自然语言 `gpt_draw` 支持 `reference_message_id`、`image_index` 和 `edit`。模型从当前会话选择原图消息，插件使用SDK读取原图字节，以Codex `-i`附图并要求作为绘图工具参考图。图片不存在、失效、跨会话或序号不符时返回失败，不退化为纯生成。原生PNG/JPEG/WebP保留文件内容；GIF/BMP转换首帧PNG。当前每次处理一张原图；多张不明确时先询问。参考图限20MB，仍受宿主RPC上限约束。原有/gpt保留。上游升级可能覆盖本地补丁，升级前需备份并复核。
